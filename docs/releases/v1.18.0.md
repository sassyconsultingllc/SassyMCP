## v1.18.0 — Built-in OAuth 2.1 authorization server

### What changed

SassyMCP's HTTP server can now act as its own OAuth 2.1 authorization
server — no Cloudflare Worker required. When the effective bind is a
loopback address over plain HTTP, or any address over HTTPS, the server
serves:

- `GET /.well-known/oauth-authorization-server` — authorization-server
  metadata, advertised at the effective bind URL.
- `POST /register` — OAuth 2.1 dynamic client registration (public
  clients supported; redirect URIs must be loopback-HTTP or HTTPS,
  no fragments/userinfo, max 10 per client).
- `GET|POST /authorize` — authorization endpoint with mandatory PKCE
  (S256). Authorization codes are single-use and expire after
  10 minutes.
- `POST /token` — authorization-code exchange and refresh-token
  rotation (30-day refresh lifetime; rotation sweeps the old grant's
  access tokens).
- `POST /revoke` — RFC 7009 revocation of access and refresh tokens.
- `GET|POST /oauth/consent` — the operator consent screen.
  `/authorize` never auto-approves: it stages the request and redirects
  here. Approval is bound to a per-flow `HttpOnly`/`SameSite=Lax`
  CSRF cookie, and on non-loopback binds it additionally requires a
  bearer token with the `admin` scope on the consent form.

OAuth-issued access tokens (1-hour lifetime) plug straight into the
existing `tokens.json` system — your CLI bearer token keeps working
unchanged, and revoked OAuth tokens stop working immediately.
OAuth client registrations and refresh-token hashes persist in
`~/.sassymcp/oauth.json` (refresh secrets are stored hashed, never raw).

Safety rails: if `SASSYMCP_OAUTH_ISSUER` is set, the built-in server
stays off and the deployment remains a pure resource server behind
that external issuer. The built-in server also stays off (with a
warning) on wildcard binds such as `0.0.0.0` over plain HTTP.

Note for API clients: the upstream MCP SDK's `/revoke` request model
requires the `client_secret` form field even for public clients — send
it empty (`client_secret=`).

### Upgrade notes

No action required — this is purely additive. Static bearer-token auth
is untouched. To try the flow, point any OAuth 2.1 / MCP client at
`http://127.0.0.1:21001` (or your configured bind): it discovers the
metadata, registers, and the operator approves each grant in the
browser. Clients are managed in `~/.sassymcp/oauth.json`.
