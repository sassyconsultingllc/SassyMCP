## v1.10.0 — Tool-discovery surface + frozen-safe selfmod

### What changed

SassyMCP can now answer "am I whole?" and "what can I do?" from the live
registry, for any MCP client. Two new always-loaded tools:

- **`sassy_self_check`** — reconciles the declared module manifest against the
  live tool registry, classifies every module `loaded` / `dormant` (on-demand
  group, absent by design) / `pruned` (low usage) / **`BROKEN`** (failed
  import → tools silently never registered), and reports which runtime you're
  on (`source` vs `frozen`), `package_root`, and `pid`.
- **`sassy_tool_catalog`** — the live `name → one-line purpose → group` map of
  every registered tool, so a client can enumerate capability without loading
  each tool's schema.

selfmod no longer hangs or returns confusing errors in a packaged build: it
detects a frozen (PyInstaller) runtime and serves honest source-only stubs. A
`/sassymcp:discover` MCP prompt and a rewritten persona first-call sequence
orient any wrapper at the start of a task.

### The bug / motivation

A cross-session handoff reported "entire tool families amputated." Nothing was
actually missing — the loader lazy-loads and usage-prunes on-demand groups by
design (`_tool_loader.get_pruned_tools`), and the reporting session had hit a
stale bundle. The two real gaps it exposed: there was no way to tell legitimate
lazy-absence from a genuine failed import, and `sassy_selfmod_status` hung on
every call in the packaged runtime — its `git`/`glob` ops ran against a
PyInstaller `_MEIxxxx` extraction dir that has no source files on disk.

### The fix / approach

- **`sassymcp/modules/meta.py`** — `sassy_self_check` reconciles
  `TOOL_GROUPS` modules vs `server._tool_manager._tools`, logging any BROKEN
  module at ERROR (loud, not silent) and self-identifying the runtime.
  `sassy_tool_catalog` derives `name→purpose→group` from the registry, so it
  never drifts from reality the way hand-written capability prose does.
- **`sassymcp/modules/selfmod.py`** — `_FROZEN = sys.frozen / _MEIPASS`
  detection; in a frozen build `register()` installs source-only stubs for all
  seven selfmod tools instead of file/git ops that can only flail. Supersedes
  the v1.9.x `rev-parse` guard, which treated a symptom.
- **`sassymcp/modules/persona.py`** — the OBSERVABILITY first-call sequence is
  now `self_check → tool_catalog → persona_full → hooks_suggest` (it previously
  ended in `sassy_selfmod_status`, the call that hangs in a bundle), plus a
  "Capability map" entry.
- **`sassymcp/modules/prompts.py`** — `/sassymcp:discover` runs the same
  orientation as a one-click slash shortcut.

### Test coverage

`tests/test_discovery.py` (5 tests): `sassy_self_check` returns
`verdict=whole`, `runtime=source`, 35/35 modules import; `sassy_tool_catalog`
enumerates the registry; the frozen branch registers all seven selfmod stubs
with `selfmod_status` answering instantly (no hang); persona bakes the
discovery protocol; the `discover` prompt registers and renders. Live check on
the running bundle: `sassy_self_check` → `verdict=whole`, 270 tools, 0 broken.

### Verification

```ps1
python tests/test_discovery.py
python -m pytest tests/test_discovery.py -q
```

Runtime / live check (by hand): call `sassy_self_check` on a connected server
and expect `verdict=whole` with a `runtime` of `source` or `frozen`; on a
`frozen` server, `sassy_selfmod_status` returns
`{"error":"selfmod unavailable in packaged build"}` instantly instead of
timing out.

### Compatibility

- Purely additive. Two new always-loaded tools and one new MCP prompt; no
  existing tool's name, args, or output shape changed.
- `selfmod_*` behaviour is unchanged when running from source. In a packaged
  build the tools now return a clear "run from source" message instead of
  hanging (`selfmod_status`) or a confusing "file not found"
  (`read`/`edit`/`write`) — a strict improvement, no migration needed.
