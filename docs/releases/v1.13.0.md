## v1.13.0 — All or nothing: tier gating removed, everything unlocked

### What changed

The pro/forensics license gate is gone. Every tool group — `github_full`,
`android`, `v020`, `linux`, `system`, `forensics`, all of them — ships
unlocked, for everyone, with no key. One release, one product, no tiers.

Licenses become **supporter keys**: `sassy_setup_license` still activates,
validates, and deactivates against LemonSqueezy, and the tier label still
shows in the startup banner, control panel, CLI wizard, and VS Code cockpit —
as supporter recognition, not as a gate. Refunds still revoke the label
(weekly LS check + fast billing-oracle check at startup).

### The bug / motivation

The gate locked 5 tool groups plus the forensics add-on behind a purchase
that could not actually complete: the LemonSqueezy checkout was unwired
(secrets unset, verified live 2026-06-23) and the client-side variant→
entitlement map was empty, so even a successful buyer would have received
the free tier. Result: every user lost the heavy automation surfaces, and
nobody could pay to get them. The gate subtracted value from all users and
produced revenue from none — locked for no reason.

### The fix / approach

- **`sassymcp/license.py`** — `get_allowed_groups()` returns
  `set(TOOL_GROUPS.keys())` unconditionally; license state affects only the
  displayed tier label. Removed `FREE_GROUPS` / `PRO_ONLY_GROUPS` /
  `ADDON_GROUPS` / `TIER_GROUPS` / `ALWAYS_ALLOWED` (no external importers);
  tier vocabulary survives as informational `KNOWN_TIERS` / `KNOWN_ADDONS`.
  The unmapped-variant warning is reworded (cosmetic label gap, still logged
  loudly at ERROR so the entitlement map gets fixed). The function is kept —
  rather than inlined away — as the single reintroduction point if a real
  buy→own loop ever ships.
- **`sassymcp/server.py`** — `_resolve_modules()` no longer consults the
  license: `SASSYMCP_LOAD_ALL=1` loads every group, `SASSYMCP_GROUPS` loads
  any known group, and the "requires Pro license — skipped" branch is gone.
  Startup revocation checks stay (they keep the supporter label honest);
  the banner's "BYPASS" special-case is removed.
- **`SASSYMCP_LICENSE_BYPASS`** is accepted and ignored — nothing left to
  bypass; old dev/CI environments that set it keep working unchanged.
- **`sassymcp/modules/setup_wizard.py`** — `sassy_setup_license` reframed as
  supporter-key management: the `status` upsell block is now a supporter
  note, and the post-activate message no longer claims tools will unlock.
- Docs: README "Licensing & Tiers" → "Licensing" (all-unlocked + optional
  supporter license), forensics "requires add-on" markers dropped from the
  module table, mcpb/README tiers section replaced.

### Test coverage

`tests/test_license_gating.py` rewritten (11 tests) to pin the new
contract: every license state (none, valid pro, forensics addon, expired,
tampered, corrupt, bypass env) returns exactly the full `TOOL_GROUPS` key
set and never raises; the supporter-label machinery (generate → parse →
validate round-trip, expiry downgrade of the label) still works.
`tests/test_lemonsqueezy.py` (22 tests) unchanged — activation, weekly
revalidation, deactivation, and fast-revocation flows all still pass.

### Verification

```ps1
python -m pytest tests/test_license_gating.py tests/test_lemonsqueezy.py -q
```

Runtime check: start the server with no license file and confirm the banner
reads `tier=free` while `groups:` lists all 18 groups; `SASSYMCP_GROUPS=android`
now loads the android group on an unlicensed install.

### Compatibility

- No tool names, args, or output shapes changed. Strictly additive for
  users: groups that previously refused to load without a key now load.
- Existing activated licenses keep working — the key validates, the tier
  label displays, deactivation still frees the LS seat.
- `SASSYMCP_LICENSE_BYPASS=1` environments: no behavior change (everything
  was unlocked for them already; the variable is now a no-op).
- Importers of the removed `license.py` tier-set constants would break —
  repo-wide search found none outside the module and its tests.
