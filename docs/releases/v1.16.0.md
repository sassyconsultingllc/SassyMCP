## v1.16.0 — Curated tool descriptions and MCP annotations for every tool

### What changed

All 278 tool descriptions were rewritten from per-tool implementation
analysis: explicit read-only/mutating/destructive disclosure, defined vague
terms with ordering and result caps, parameter semantics with defaults and
interactions (compensating for 0% schema parameter-description coverage), and
named sibling guidance ("use X instead of Y when Z"). MCP `ToolAnnotations`
(`readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`) are now
set explicitly on every tool: 154 read-only, 40 destructive, 212 idempotent,
146 open-world. Metadata lives in the generated
`sassymcp/tool_descriptions.py` and `sassymcp/tool_annotations.py`, applied at
registration in `server._apply_tool_metadata()`; per-tool source is untouched.

The release also folds in the pre-release security audit fixes (below),
experimental iPhone support (6 tools, `iphone` group) via libimobiledevice,
plus ~60 medium/low hardening fixes.

### The bug / motivation

Tool descriptions are the contract agents reason about: vague descriptions
produced wrong-tool selection, and missing `ToolAnnotations` meant MCP clients
could not gate destructive calls. The schema parameter-description coverage
was 0% — agents had to guess parameter semantics, defaults, and interactions.

### The fix / approach

Two generated modules, one wiring point:

- `sassymcp/tool_descriptions.py` — 278 curated descriptions, written from
  each tool's source (not from the old text).
- `sassymcp/tool_annotations.py` — all four MCP annotation booleans set
  explicitly per tool; do not rely on spec defaults. Policy: `destructiveHint`
  only for data deletion, silent overwrites of non-designated output, or
  system/device/registry mutation; `readOnlyHint` only when the tool performs
  no state mutation at all; `idempotentHint` false for state-consuming or
  compounding side effects; `openWorldHint` for network/external/device touch.
- `server._apply_tool_metadata()` applies both at registration, before the
  schema-version hash, so the wire schema clients see carries them.

### Pre-release security audit fixes

A source-code audit of the release candidate found and fixed, before tagging:

- **SSH guard bypass (residual from 1.15.2):** the exec-option regex missed
  `` `ssh -o ProxyCommand=...` `` inside backticks; the boundary class now
  covers command substitution. Guard test battery extended (29 cases).
- **Sensitive-read denylist enforced:** `is_sensitive_read_path()` (`~/.ssh`,
  tokens, SAM hives, `/etc/shadow`, …) is now called by every file-content
  read path (`sassy_read_file`, `sassy_read_multiple`, `sassy_search_files`,
  `sassy_file_info`, `sassy_diff`, `sassy_edit_block`, `sassy_edit_multi`);
  refusals are enforced in all permission modes and audit-logged.
- **Privilege-escalation gating:** `sassy_permission` switching to
  `mode=bypass` now requires `confirm='YES'`; control-panel settings/rules
  mutations now write audit events with actor and old→new values.
- **Annotation coherence:** adopted one `destructiveHint` policy (destructive
  only for data deletion, silent overwrites of non-designated output, or
  system/device/registry mutation — not for writing requested export files)
  and corrected 13 contradictions (`sassy_reg_write`, `sassy_reg_export`,
  `sassy_audit_clear`, `sassy_gh_protect_branch`, screenshot/archive tools…).
- **Zip-slip:** `sassy_unzip` now validates with `os.path.commonpath`.
- **Transport hardening:** crosslink no longer reflects
  `Access-Control-Allow-Origin: null`; `server.key` and the panel token get
  `0600` + Windows ACL lockdown; `SASSYMCP_AUTH_TOKEN` charset is validated
  at startup (fail closed).
- **Android failure contracts:** `phone_screen` tools now report explicit
  missing-adb/timeout errors instead of silent empty strings.

### Experimental iPhone support

New `iphone` tool group (6 tools) backed by
[libimobiledevice](https://libimobiledevice.org/): `sassy_iphone_list`,
`sassy_iphone_info`, `sassy_iphone_screenshot`, `sassy_iphone_syslog`
(bounded capture), `sassy_iphone_apps`, `sassy_iphone_install`
(`confirm='YES'`). Per-host-OS install hints, `udid` targeting for multiple
devices, and graceful degradation (install hint or pairing reminder, never a
traceback) when the binaries or a trusted device are missing. The group is
opt-in (`always_load: false`); enable with `SASSYMCP_GROUPS` or
`sassy_tool_group_toggle`.

- `tests/test_ssh_exec_guard.py` — 29 cases: the backtick
  command-substitution bypass plus every sibling option, glued/spaced/quoted
  `-o` spellings, wrapped invocations, `scp`/`sftp`, config-file injection,
  `~/.ssh` traversal, and the false-positive set that must keep running.

  gate, `udid` targeting, and syslog capture bounds.

  exactly 278 entries, matching the registered tool count.

### Compatibility

Tool names, schemas, and behavior are unchanged — descriptions and annotations
are metadata; clients that ignore annotations see no change. Breaking **only**
for inputs the audit fixes intentionally refuse: ssh-family exec options /
non-`~/.ssh` config files (same surface as v1.15.2), `sassy_permission`
`mode=bypass` without `confirm='YES'`, and reads of sensitive paths (refused
in every permission mode).

### Known limitations

- The macOS universal binary is unsigned and not notarized: Gatekeeper
  quarantines it on first download ("unidentified developer"); clear with
  `xattr -dr com.apple.quarantine sassymcp-macos` or right-click → Open.
  Signing/notarization is deferred — it requires an Apple Developer account
  and signing secrets, and is flagged as a future step in
  `.github/workflows/release.yml`.
